# H7 — primera entrega: instaladores de prueba

Estado: en desarrollo; instaladores independientes para macOS **Apple Silicon**, Windows amd64
y Ubuntu **24.04 amd64**. macOS Intel queda fuera por petición del propietario (2026-09-25).
La conexión comercial entre AIBID y el futuro proyecto del servidor se deja para el final de ambos proyectos.

## Alcance de esta entrega

Canal **AIBID Pruebas 0.7.0-test.1**, licencia de desarrollo habilitada, sin servidor comercial.
Se utiliza el mismo backend/frontend H6. El binario identifica `installer-test` mediante `version`.
Puerto **18090**, solo loopback; la instalación anterior en 8090 sigue siendo independiente.
No se registran excepciones de firewall ni se publican servicios en Internet.

| SO | Paquete | Servicio / cuenta | Configuración y datos |
| --- | --- | --- | --- |
| macOS 13+ Apple Silicon | `AIBID-Pruebas-0.7.0-test.1-macOS-arm64.pkg` | launchd `app.aibid.test` / `_aibidtest` | `/Library/Application Support/AIBID-Test/data/` |
| Windows 10/11 x64 | `AIBID-Pruebas-0.7.0-test.1-Windows-amd64.exe` | `AIBIDTest` / `NT SERVICE\AIBIDTest` | `%ProgramData%\AIBID-Test\` |
| Ubuntu 24.04 amd64 | `aibid-test_0.7.0~test.1_amd64.deb` | systemd `aibid-test` / `aibid-test` | `/etc/aibid-test/config.json`, `/var/lib/aibid-test/` |

Los instaladores no tienen firma de distribución/notarización ni certificación comercial.
El ejecutable macOS tiene firma ad hoc para ejecución arm64. Los SHA256 permiten comprobar
integridad; **no sustituyen una firma de editor**. No deshabilitar globalmente Gatekeeper/SmartScreen.
Utilizar las opciones del sistema para permitir únicamente este archivo de prueba si se bloquea.

## Instalar y abrir

### Mac M1 Max

1. Si faltan dependencias, instalarlas como tu usuario con `brew install poppler tesseract tesseract-lang`.
   El servicio usa ejecutables de `/opt/homebrew/bin`. Homebrew y OCR no van dentro del .pkg.
2. Abrir el `.pkg` y completar la instalación con una cuenta administradora de macOS.
3. Abrir **Aplicaciones → AIBID Pruebas → Configurar AIBID.command**. Puede solicitar primero
   la contraseña de macOS. El diagnóstico comprueba herramientas, idiomas y dos PDF reales.
4. Crear usuario/nombre/contraseña de AIBID (mínimo 6 caracteres) en esa terminal local.
5. Abrir **http://127.0.0.1:18090**. Ya se puede cerrar Terminal.

El servicio no inicia antes de crear el administrador. Si se corrigen herramientas o permisos,
ejecutar de nuevo Configurar. Los permisos privados del estado son 0700/0600.
Para una raíz de biblioteca de prueba independiente:

```sh
sudo install -d -o _aibidtest -g _aibidtest -m 700 /Users/Shared/AIBIDPruebas
```

Esa es una raíz elegible desde la aplicación; no usar la carpeta privada de estado como biblioteca.
macOS puede restringir acceso a Documentos/Escritorio por su protección de privacidad.
Para esta primera prueba usar la carpeta dedicada, sin otorgar acceso amplio al disco.

Desinstalar: **Aplicaciones → AIBID Pruebas → Desinstalar AIBID.command**.
Conserva datos, raíces, cuenta de servicio y marcador de versión; permite reinstalar la misma versión.

### Windows

1. Ejecutar el `.exe` como administrador. Incluye PDF/OCR e idiomas español e inglés.
2. Inicio → **AIBID Pruebas → Configurar AIBID Pruebas**. Aceptar la elevación de Windows.
3. Completar diagnóstico y crear administrador. El servicio pasa a inicio automático diferido.
4. Abrir **http://127.0.0.1:18090** y cerrar la consola de configuración.

Los ejecutables quedan en `%ProgramFiles%\AIBID-Test`. Datos privados: solo SYSTEM,
Administradores y la cuenta virtual del servicio. La CLI conserva el acceso del servicio
cuando un administrador crea o recupera cuentas. No hay contraseña Windows de servicio.
Dar permiso Modificar a `NT SERVICE\AIBIDTest` solo sobre las raíces elegidas (Lectura si son vinculadas).
Las unidades de red mapeadas por el usuario no se heredan al servicio; las pruebas UNC/NAS
requieren cuenta/permisos del recurso y quedan en la matriz operativa posterior.

Desinstalar desde Aplicaciones de Windows. Se conservan `%ProgramData%\AIBID-Test` y las bibliotecas.
Diagnóstico manual, en PowerShell administrador:

```powershell
& "$env:ProgramFiles\AIBID-Test\manage.ps1" -Action Doctor
```

### Ubuntu

```sh
sudo apt install ./aibid-test_0.7.0~test.1_amd64.deb
sudo aibid-test-admin
```

APT resuelve las dependencias de PDF/OCR. Abrir **http://127.0.0.1:18090** en ese equipo.
El servicio no tiene privilegios root; la instalación/administración local sí requiere sudo.
Para una raíz dedicada: `sudo install -d -o aibid-test -g aibid-test -m 700 /srv/aibid-pruebas`.
Estado: `systemctl status aibid-test`; log: `journalctl -u aibid-test -n 100 --no-pager`.
Desinstalar: `sudo apt remove aibid-test`. Incluso `purge` conserva datos y configuración.

### Ubuntu sin conexión

El `.deb` solo no contiene dependencias. Preparar en Ubuntu 24.04 amd64 **con Internet**:

```sh
sudo bash packaging/ubuntu/prepare-offline.sh ./dist/installers/aibid-test_0.7.0~test.1_amd64.deb /var/tmp/aibid-offline
```

Si solo copiaste `dist/installers`, los dos scripts también van en `ubuntu-offline/`; desde esa
carpeta de instaladores: `sudo bash ubuntu-offline/prepare-offline.sh ./aibid-test_0.7.0~test.1_amd64.deb /var/tmp/aibid-offline`.

El script resuelve dependencias contra un estado dpkg vacío, descarga el cierre de dependencias,
crea índice local y hashes. Copiar toda la carpeta (ruta sin espacios) a la máquina aislada y ejecutar
`sudo bash install.sh`. APT usa únicamente ese repositorio local sin modificar fuentes permanentes.
Pendiente ejecutar esto en tu Ubuntu y certificarlo en una VM limpia con red deshabilitada.

## Reinstalación y límites deliberados

Se puede reinstalar **la misma versión** conservando JSON, usuarios, DB, licencia, archivos y OCR.
La desinstalación elimina programa/servicio; conserva configuración, datos y raíces externas.
El instalador rechaza datos marcados como otra versión antes de reemplazar código.
Todavía no se ofrece actualización N-1 ni downgrade: requieren backup/restore integral verificado
y manifiestos de actualización firmados con claves distintas de las licencias.
Los instaladores comerciales se construirán en un canal distinto, sin bypass ni claves de prueba.

## Construcción reproducible de los paquetes de prueba

```sh
npm --prefix web run build
python3 scripts/build_installers.py --target macos
python3 scripts/build_installers.py --target ubuntu
python3 scripts/build_installers.py --target windows --windows-tools /ruta/prefix-win64 --makensis /ruta/makensis
```

Requiere Go según go.mod, Node según package.json; macOS requiere pkgbuild/productbuild/codesign.
El creador `.deb` usa el formato ar + control/data tar.gz estándar sin instalar dpkg en macOS.
Windows requiere NSIS (usado: 3.12) y Micromamba (usado: 2.9.0). Restaurar el runtime fijado con
`micromamba create --no-rc --platform win-64 --prefix /ruta/prefix-win64 --file packaging/windows/ocr-explicit.txt`.
El builder verifica el conjunto contra `packaging/windows/ocr.lock.json` y comprueba hashes de
DLL/ejecutables/idiomas contra los metadatos de los paquetes. También comprueba importaciones
estáticas PE amd64 para detectar DLL ausentes. El lock contiene 52 paquetes de conda-forge,
incluidos Poppler 26.09.0 y Tesseract 5.5.3. NSIS fuera de su ruta habitual necesita `NSISDIR`.
Nunca ejecutar estas compilaciones simultáneamente con el build frontend, que reemplaza assets embebidos.

Salida: `dist/installers/`, instrucciones, PDF de prueba y `SHA256SUMS`.
Los builds cruzados prueban compilación; **no** demuestran servicio/ACL/OCR nativos de Windows o Ubuntu.
La instalación real del servicio Mac modifica /Library y requiere la autorización normal del instalador;
los ensayos locales del proyecto deben usar carpetas temporales, sin tocar la instalación anterior.
