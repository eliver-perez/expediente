# H2 — Identidad, sesiones y auditoría

Implementación autorizada al aprobar el propietario D-01 a D-05. Este módulo se
puede compilar y ejecutar; las funciones documentales continúan en H3–H7.

## Entrega

- CLI local: `init`, `bootstrap`, `recover-admin`, `migrate`, `rollback-empty`, `serve`.
- Configuración privada, escucha loopback inicial, TLS directo o proxy explícito.
- SQLite embebido `modernc.org/sqlite` 1.59.0, WAL, FULL, FKs por conexión, un escritor
  y cuatro lectores como máximo. Verificación de FTS5 y versión con corrección WAL.
- Migración 0001 con checksum, transacción y rechazo de esquemas de versiones
  futuras. Reversión únicamente mientras DB/auditoría estén vacías.
- Argon2id 64 MiB / 3 pasadas / paralelismo 1; dos hashes simultáneos como máximo.
- Cookies opacas HttpOnly/SameSite; Secure y prefijo `__Host-` bajo HTTPS. CSRF,
  validación de Origin/Host, JSON acotado y sin claves repetidas, cabeceras de seguridad.
- Login nuevo reemplaza sesión anterior atómicamente; auditoría fallida revierte
  toda la sustitución. Cada endpoint comprueba sesión y cada mutación la revalida
  junto con permisos en la transacción de negocio.
- Cambio/restablecimiento de contraseña y revocación/deshabilitación cierran sesiones.
  Protección del último administrador habilitado y revisiones optimistas de usuario.
- Rate limits persistentes por identificador/IP, reservas antes del hash y espera
  progresiva; no se reinician al reiniciar el proceso. Intentos fallidos sin sesión.
- Historial propio y global, roles de administración/auditor separados, bitácora
  append-only con eventos transaccionales y consultas paginadas por cursor.
- React local sin CDN: acceso, Mi cuenta, usuarios/permisos, accesos y eventos.
  Sondeo cada 30 segundos y al recuperar foco; no prolonga inactividad. Actividad
  de teclado/puntero actualiza la sesión como máximo una vez por minuto.

La creación/configuración de bibliotecas y asignaciones por biblioteca se materializan
en H3, cuando existe esa entidad. H2 entrega permisos globales y no concede acceso
documental por ser administrador. El SQL completo H1 sigue siendo una referencia.

## Pruebas y criterios

`make check`: formato, compilación/tipado frontend, vet, tests de integración/race,
política de licencia según build tag y verificación H1. `make test-e2e`: Chrome,
tres escenarios completos y bases temporales independientes del estado real.

| Criterio H2 | Evidencia automatizada |
| --- | --- |
| ACC-01: sesión nueva sustituye anterior | Login Go concurrente; dos contextos Chrome, aviso exacto por sondeo sin interacción |
| ACC-02: fallos auditados y límites persistentes | Usuario inexistente, ausencia de secretos, nuevo servicio reutiliza contadores SQLite |
| ACC-03: contraseña/concurrencia/rollback | Login concurrente, reset vs login, cambio/restablecimiento revoca, fallo inyectado de auditoría conserva sesión anterior |
| Autorización | API niega usuarios/auditoría a cuenta ordinaria; permiso retirado se revalida al escribir; último admin protegido |
| Transporte | CSRF, JSON repetido, origen/host ajenos, IP falsificada, proxy explícito y cookie HTTPS |
| Persistencia | WAL/FTS5/FKs, backup API del driver con contenido WAL, checksum y lock exclusivos |
| Reversión | Down en DB vacía, negativa si hay auditoría y conservación de evidencia tras rollback |

La prueba de backup valida el driver: no es todavía la operación de respaldo
consistente de documentos/configuración/licencia, que corresponde a H7.

## Límites de esta entrega

El proceso Go se ejecuta en primer plano y cierra ordenadamente con Ctrl+C/SIGTERM.
Registro automático como servicio del SO e instaladores se entregan en H7. Las
compilaciones cruzadas prueban compilación, no ACL/servicios en equipos Windows o
Linux reales. El workflow de CI está preparado; sus ejecuciones remotas aún no
constituyen evidencia local de esta entrega.

El cliente de licencia comercial no está implementado: seguridad/recuperación
están habilitadas, operaciones documentales denegadas en build normal. El permiso
simulado de desarrollo solo se compila con `-tags development`; no hay claves ni
contratos modificados. El servidor E2E solo se compila con `-tags e2e`; nunca usarlo
para instalar el producto.

No se aplican purgas automáticas de accesos/auditoría en H2. La caducidad se
comprueba en cada acceso; el historial de una sesión que ya superó su timeout
sin otra petición puede mantener `closed_at=null` hasta comprobarse o sustituirse.
La autorización no depende de ese campo por sí solo: compara tiempos/credenciales.

Las operaciones de credenciales y alta de usuario no usan replay de cuerpos con
contraseñas. Username único evita altas duplicadas; después de una respuesta
perdida se consulta la lista antes de repetir. Cambios de datos/roles usan If-Match.
Idempotencia documental persistente se implementará con sus comandos H3/H4.
