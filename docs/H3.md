# H3 — Bibliotecas vinculadas, vigilancia y búsqueda

El propietario autorizó continuar H3 y redujo el mínimo de contraseña a **6
caracteres**. El máximo sigue en 128; no se modifican Argon2id, sesiones ni límites
de acceso. Backend, formularios y documentación aplican el mismo mínimo.

## Alcance implementado

- Bibliotecas vinculadas con gestor asignado explícitamente, lectores y auditores.
  La administración global permite recuperar permisos; no concede lectura documental.
- Alta de múltiples raíces mediante inspección y plan de 15 minutos, revalidación
  de identidad y revisión al confirmar, conflictos entre bibliotecas sin revelar
  sus rutas, vistas lógicas de subcarpetas y consolidación de raíces propias.
- Consolidación transaccional: conserva documentos, versiones, páginas, FTS,
  historial y permisos; sustituye ubicaciones y adapta vistas. No mueve originales.
- Pausa, intervalo configurable, retiro con plan y recuento; conservar índice o
  retirar sus referencias. La raíz retirada sigue participando en colisiones.
- Identidad de SO y creación cuando están disponibles; hard links dentro de una
  biblioteca comparten documento. SHA-256 informa copias sin fusionarlas.
- Escaneo por lotes de 128 entradas, checkpoint persistente por directorio,
  comparación de metadatos durante lectura y ventana de estabilidad de 2 segundos.
  Solo un recorrido completo de la misma raíz puede confirmar ausencias.
- Watcher fsnotify recursivo mediante registro de cada directorio, debounce de
  750 ms, barrera de reconciliación ante eventos durante un escaneo, recuperación
  de pérdida de eventos y polling. Reconciliación inicial cada 15 minutos.
- Cola SQLite, trabajadores configurables, leases y fencing, recuperación al
  reiniciar, hasta cinco intentos para fallos transitorios y reintento manual
  enlazado a su tarea original. Un solo trabajo por archivo o raíz a la vez.
- Extracción nativa por página con Poppler; OCR Tesseract en páginas con menos de
  32 letras/dígitos extraíbles. Español inicial; inglés o ambos por biblioteca.
  Cambiar idioma encola extracción de las versiones actuales.
- Snapshot privado del PDF comprobado por SHA-256, sin shell; salida, páginas,
  resolución, concurrencia y duración acotadas. Publicación de páginas y FTS en
  una transacción y únicamente para la versión y lease actuales.
- Texto anterior disponible si falla el reemplazo. Ausencia conserva texto,
  metadatos y resultados; original/descarga responden `DOCUMENT_UNAVAILABLE`.
  Cambios A→B→A generan dos avisos; un nuevo escaneo sin cambios no los repite.
- Búsqueda por nombre o texto, frases, acentos y códigos con guiones; parámetros
  SQL y compilador de términos literales FTS. Comillas sin cerrar devuelven error
  claro. Resultados con página, segmentos resaltados, disponibilidad y cursor.
- Auditoría conserva consulta EXACTA, tipo, filtros, bibliotecas efectivamente
  consultadas y total de documentos. Ver esos detalles exige permisos de auditor
  en todas las bibliotecas de la consulta; el gestor no los recibe por defecto.
- React local: bibliotecas, raíces/planes/vistas, personas, cola, explorador por
  carpetas, duplicados, buscador, ficha PDF/texto retenido, historial y avisos.

## Ejecutar para desarrollo

La licencia comercial se implementa en H6. El build de desarrollo habilita de
forma explícita las operaciones documentales y no debe distribuirse como producto:

```sh
make build-dev
./build/gestor-documental-dev serve
```

Se reutiliza la configuración y administrador de H2. Si aún no existen, ejecutar
`init` y `bootstrap` con este mismo binario antes de `serve`. El estado se migra al
abrirlo. H2 conserva contraseñas, usuarios, sesiones y auditoría. Cerrar cualquier
servicio anterior antes de iniciar otro sobre el mismo estado.

Abrir `http://127.0.0.1:8090`, crear una biblioteca, confirmar la asignación de gestor
y abrir **Carpetas → Inspeccionar carpeta → Registrar e indexar**. Consultar avances
con **Procesamiento → Actualizar tareas**. La raíz pertenece al servidor; el
navegador no sube ni copia una carpeta del equipo remoto.

Se requieren `pdfinfo`, `pdftotext`, `pdftoppm` y `tesseract`, con datos `spa`.
Verificación local: Poppler 26.08.0, Tesseract 5.5.0 y datos `tesseract-lang` 4.1.0.
Poppler y los datos de idioma se instalaron mediante Homebrew.
Los ejecutables del producto continúan sin CGO; las herramientas externas deben
estar disponibles al ejecutar el servicio. Sus instaladores se preparan en H7.

La sección opcional `indexing` del archivo de configuración acepta:

```json
{
  "pdfinfo": "pdfinfo",
  "pdftotext": "pdftotext",
  "pdftoppm": "pdftoppm",
  "tesseract": "tesseract",
  "workers": 1,
  "maximum_file_mb": 256,
  "maximum_pages": 1000,
  "page_timeout_seconds": 120
}
```

El JSON anterior es el contenido de `indexing`, no un reemplazo de toda la config.
También se aceptan rutas absolutas a ejecutables. Dos límites adicionales son
32 MiB de texto por documento y una hora por intento de trabajo. El raster OCR se
limita a 2500 píxeles en su dimensión mayor; Tesseract usa un hilo por proceso.

## Persistencia y compatibilidad

`0002_linked_libraries.up.sql` crea solo entidades necesarias para H3. No crea
expedientes, cargas, workflow ni licencias comerciales. El SQL de H1 sigue siendo
el modelo de referencia completo; la tabla `documents` se ampliará mediante otra
migración en H4. Nunca modificar una migración ya entregada a una instalación.

La reversión automática solo procede sobre una base nunca utilizada. El down H3
exige cero bibliotecas y el down H2 protege usuarios/accesos/auditoría; ambos se
aplican en una transacción. Una reversión rechazada no deja el esquema a medias.
La recuperación de datos reales exige un respaldo consistente compatible.

SHA-256 de `0002_linked_libraries.up.sql`:
`38e1bfe489db3270b065322680492076c309195e740ecdc17d5bf61d7f4654b3`.
La migración H2 y `LICENSE_CONTRACT.md` conservan sus bytes originales.

## Verificación

```sh
make check
make test-e2e
```

Las pruebas H3 se compilan con `-tags development`; los tests normales verifican
que el permiso simulado esté excluido. Los fixtures PDF son propios y sintéticos:
`testdata/documents/native.pdf` y `scanned.pdf`, reproducibles con
`scripts/create_pdf_fixtures.py`. No contienen documentos de clientes.

Pruebas implementadas: texto nativo/OCR español real; renombrado; hard links;
reaparición; raíz desconectada simulada sin falsas eliminaciones; consolidación
con IDs/FTS intactos; acceso entre bibliotecas; ocultamiento de rutas a lectores;
texto retenido tras fallo OCR; cambio A→B→A; colisiones/subcarpetas/symlinks;
paginación y consulta exacta; permisos de auditor; máximo de intentos, fencing,
reinicio y watcher real con directorios nuevos y pérdida de eventos inyectada.
La migración se prueba también desde H2 con usuarios y auditoría existentes.

El escenario de navegador H3 crea una biblioteca, indexa ambos PDF, crea una vista,
explora carpetas, busca una frase, abre texto/ficha, simula ausencia y confirma que
el texto continúa disponible, incluido el diseño móvil de 390 px.

## Límites y decisiones de esta etapa

- Probado localmente en macOS arm64. La simulación de desconexión no equivale a
  ensayar un NAS real. ACL, junctions/UNC, montajes remotos, instaladores y pruebas
  nativas en la matriz completa requieren los equipos y escenarios de H7.
- Root handles de Go evitan escapes de ruta durante aperturas. Se omiten enlaces
  internos y se rechazan cambios inesperados de volumen; no se siguen montajes
  internos sin validación. DB, programa y documentos no pueden superponerse.
- Si un filesystem Linux no ofrece fecha de creación, una reaparición con inode
  potencialmente reutilizado queda en diagnóstico; no se fusiona automáticamente.
- Reorganizar propiedad entre bibliotecas se rechaza. Consolidar raíces propias
  sí se ejecuta. Los cambios documentales de managed/hybrid y expedientes son H4/H5.
- Un archivo inaccesible o que excede el presupuesto impide confirmar ausencias
  en ese recorrido. Los datos ya observados y el texto previo se conservan.
- El límite de concurrencia, salida, raster y tiempo reduce consumo; no es un
  sandbox completo para vulnerabilidades de los parsers externos. El aislamiento
  por SO y ensayos de carga/recuperación forman parte del endurecimiento H7.
- No hay purga automática de versiones, escaneos ni auditoría. La consolidación
  de metadatos usa una transacción; medir corpus grandes antes de fijar capacidad.
- Avisos pendientes y grupos de duplicados se limitan a 100 por consulta. Jobs,
  eventos, carpetas y búsqueda tienen cursor. La ficha muestra los primeros 50
  eventos del documento; el endpoint permite consultar las páginas siguientes.
- Cada petición HTTP de contenido deja auditoría; agrupar peticiones Range de una
  misma apertura es parte del endurecimiento H7.
